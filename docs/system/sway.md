# Sway Window Manager Architecture & Reference

Architectural standards, window rules, workspace layout, and modular keybindings for Sway (Wayland) on CachyOS.  
Use this document as the single source of truth for window management and display orchestration.

---

## 1. Modular Configuration Architecture (`~/.config/sway/config.d/`)

To ensure token efficiency for AI agents and maintainability for developers, the monolithic 680+ line configuration is structured into logical subcategory files:

| File | Purpose | Lines / Scope |
| :--- | :--- | :--- |
| `00-variables.conf` | Modifiers (`$mod = Mod4`), workspace definitions (`$ws1`–`$ws10`), font, defaults. | Variable declarations |
| `10-display.conf` | `eDP-1` display output mode, 165Hz refresh, cursor theme/size, border styles, theme colors, `apply-vibrance` reload hook. | Display pipeline |
| `20-input.conf` | Keyboard repeat rates, touchpad natural scroll, pointer accel, 3-finger/4-finger gestures. | Input devices |
| `30-window-rules.conf` | Floating utilities (`bluetui`, `wifui`, `rofi-network`, `me3-manager`, `ds3-randomizer`, `cycles-installer`), Thunar rules, Brave tabbed view, Steam shell focus management, Workspace 4 gaming rules. | Window assignments |
| `40-keybindings.conf` | Window navigation, workspace switching, scratchpad toggles, launchers (`rofi-network` on `$mod+Mod1+5`, `bluetui` on `$mod+Mod1+2`), current-theme wallpaper cycling (`Win + Shift + W` / `Win + Ctrl + W`, plus reverse on `Win + Ctrl + Shift + W`), cursor theme/size hotkeys, validated reload on `Win + Shift + R`. Marks system removed 2026-10-18. | Key chords |
| `45-ui-scale.conf` | Output-scale keybindings backed by `ui-scale`; generated runtime state is written to `99-ui-scale.conf`. | Central UI scale controls |
| `50-gaming-mode.conf` | Passthrough gaming mode (`mode "gaming"` via `Alt + Shift + F`), muted shortcuts, game hotkeys. | Gaming isolation |
| `60-autostart.conf` | D-Bus/systemd session imports, daemons (`mako`, `polkit`), night light, wallpaper, game-workspace-daemon. One-shot initialization uses `exec` so ordinary Sway reloads do not restart long-running helpers. | Session bootstrap |
| `70-bar.conf` | Native `swaybar` inclusion and dock/hide state restore. | Status bar |
| `80-theme-colors.conf` | GENERATED by `theme-set` (do not edit). Tabbed windows retain their authored accent as a narrow focus border, but use calm, neutral-blended background surfaces and contrast-checked text for selected/unselected tabs. Generated and live IPC rules match, surviving Sway reloads. | Theme tab/border persistence |
| `99-ui-chrome.conf` | GENERATED by `ui-sync`; scale-adjusted Sway title/tab chrome. | Runtime-generated chrome state |
| `99-ui-scale.conf` | GENERATED by `ui-scale`; persisted runtime output scale. Deliberately not tracked as a fixed chezmoi state. | Runtime-generated scale state |

The root entrypoint (`~/.config/sway/config`) contains:
```ini
include ~/.config/sway/config.d/*.conf
```

## 2. Hardware & Display Pipeline

* **Display Output:** ASUS TUF Gaming F16 built-in display (`eDP-1` in the current 2026-10-31 session; connector names are not assumed permanent).
  * Resolution: `1920x1200` (16:10 aspect ratio).
  * Refresh Rate: approximately `165.004Hz`.
  * Current runtime UI scale: `1.30`.
  * `10-display.conf` owns mode/refresh/adaptive-sync/tearing policy; it deliberately does not hardcode scale.
  * `ui-scale` owns compositor scaling and atomically persists it in generated `99-ui-scale.conf`.
  * `ui-sync` derives scale-aware system chrome and skips writes/reloads when generated content is unchanged. Mako notification/OSD sizing is controlled by the `MAKO_*` values in `~/.config/ui-metrics.conf`; the current compact bases are font 15, padding/margin 8, width 440, and radius 6. With `CHROME_FOLLOW=0` these are divided by output scale, keeping brightness/volume/night-light/general notifications physically compact.
  * Adaptive Sync: `off` (prevents panel backlight flickering/gamma shifts on 165Hz laptop panels).
  * Allow Tearing: `yes` (reduces frame delivery latency in fullscreen gaming).
* **GPU Strategy:**
  * Machine supports dynamic GPU architectures via `supergfxctl` (`Integrated`, `Hybrid`, and `AsusMuxDgpu`).
  * Direct dGPU MUX connects RTX 5050 Mobile directly to eDP-1 with hardware vibrance via `nvibrant`.

## 4. Window Navigation & Scratchpad Architecture

* **Vim-Style Focus:** `Win + h` (Left), `Win + j` (Down), `Win + k` (Up), `Win + l` (Right).
* **Move Windows:** `Win + Shift + h/j/k/l`.
* **Splits:** `Win + b` controls the current split orientation; the former `Win + Shift + b` split binding is intentionally removed to avoid accidental nested containers beside the browser launcher.
* **Fullscreen:** `Win + f` (Toggle fullscreen).
* **Floating / Tiling Toggle:** `Alt + Shift + Space` (toggles the floating STATE of the focused window).
* **Focus Layer Toggle:** `Shift + Space` (swaps focus between the foreground floating window and the background tiled/tabbed layer underneath, via toggle-floating-focus).
* **Smart Layout Toggle:** `Win + ;` (`~/.local/bin/smart-layout-toggle`) seamlessly toggles windows between side-by-side tiling (`splith`) and tabbed presentation (`tabbed`) in place. It operates directly on the shared parent container without container-nesting marks or `move to mark` wrapping, and flattens orphaned single-child split wrappers so single-window workspaces (such as Brave on Workspace 2) retain edge-to-edge presentation without container representation chrome (e.g. `H[T[...]]`). The legacy `$mod+Shift+b split h` binding adjacent to `$mod+b` (browser launcher) has been removed to prevent accidental container splitting.
* **Window Graceful Close:** `Win + q` (polite WM_DELETE close).
* **Window Force Kill:** `Win + BackSpace` (SIGKILL via `force-kill-window`).
* **Media Play/Pause:** `Win + Alt + P` calls `~/.local/bin/media-play-pause`, which toggles the active MPRIS player with `playerctl` and shows a short Mako notification for the resulting `Playing` / `Paused` state. The helper is one-shot with no resident process. The former Aura preset bindings moved to `Win + Alt + [` (previous preset) and `Win + Alt + ]` (next preset).
* **Windows VMs:** `Alt + W` now opens/reuses X-Lite (Windows 10) on workspace 5; `Super + Alt + W` retains Nano11 (Windows 11) on workspace 10. Both `Alt + W` and `Alt + Shift + W` are active even with shortcut inhibition. `Super + Ctrl + 5` opens/reuses X-Lite (Windows 10) on workspace 5, including while shortcuts are inhibited; `Super + 5` only switches there. The preexisting `Super + Alt + 5` network menu is preserved. `Alt + Shift + W` opens the shared Windows 10/11 management menu (`rofi-windows` with native Fuzzel frontend). Its user-facing menu now shows only Open Windows, Show/Hide Windows FPS / UPS, Stop Windows and Restart Windows with Gruvbox-Dark icons, without VM version labels or high-CPU pause warnings. It targets the currently active guest, or X-Lite if both are stopped. This menu never starts both guests, and the shared Intel VF/KVMFR mutual exclusion remains enforced by the launchers. The applications launcher also contains `Windows 10 (X-Lite)`. Nano11 uses Right Ctrl for Looking Glass capture release; X-Lite now defaults to **Right Ctrl** again after the F12-only configuration proved inconsistent with the intended control; `WIN10LAB_ESCAPE_KEY=KEY_F12` remains an explicit fallback (`CapsLock+=` through xremap). * **Current-Theme Wallpapers:** `Win + Shift + W` and `Win + Ctrl + W` advance through the active theme's allowed wallpaper set; `Win + Ctrl + Shift + W` goes backward. GitHub-backed Omarchy themes are theme-scope-authoritative and cycle only their own images under `~/.local/share/theme/wallpapers/upstream/<theme>/`. Discovery version 3 restricts built-ins inside shared monorepos to their canonical wallpaper root (for example Everforest only `themes/everforest/backgrounds/`), and cached cycling applies that filter even before a legacy manifest is repaired. They do not run repository discovery, network fetching, notification, or `wset` when cycling cannot change the image; multi-image cycling and explicit `fetch`/`refresh` remain available.

### Alt+Space application launcher

`Alt + Space` launches native Wayland Fuzzel. Its compact proportions remain `width=36` and `lines=10`; `image-size-ratio=0` disables the separate large selected-app preview. `ui-sync` derives `line-height` from `FUZZEL_LINE_HEIGHT=26` in `~/.config/ui-metrics.conf`; at the current 1.30 compositor scale this generates a 20px logical row, about a 26px physical row/icon target, while the font remains 14px logical. This keeps the original minimal shape while making list icons modestly larger than the old font-metric default.

### Utility TUI Windows

The compact hardware/network TUIs use dedicated Foot client overrides instead of inheriting the global terminal font: `wifui` and `bluetui` use 15pt Iosevka Mono in centered 900x600 floats; `rogtui` uses the same 15pt override in a centered 900x680 float. This keeps utility panels readable at the current output scale without changing `foot.ini` globally.

### Scratchpads (`~/.local/bin/scratch-toggle`)
Canonical dimensions: `1700x1050` base geometry, centered on display. On scaled Wayland outputs (such as 1.30x on 1920x1200), `scratch-toggle` caps window dimensions to `SCRATCH_SCALE_PCT` (default 90%, producing 1328x830 logical pixels) to ensure full horizontal width for multi-column terminal applications (such as btop memory and disks meters) while remaining centered. Windows are **lazy-loaded on demand** on initial hotkey press to eliminate idle RAM waste:
1. **Terminal Scratchpad:** `Alt + \`` or `Ctrl + Space` (Guarded: `SCRATCH_GAME_GUARD=1` silent no-op when game focused). Its dedicated Foot override is 16 pt, slightly smaller than the global terminal so the scratch window fits more output without changing other terminals.
2. **Notes Scratchpad:** `Win + n` (Spawns/toggles Neovim on `~/notes.md`).
3. **Spotify Scratchpad:** `Win + m` (Spawns/toggles Spotify window).
4. **Video Player (mpv):** `Win + -` or `Win + _` (1280x720 floating scratchpad).
5. **Desktop Commander Scratchpad:** `Win + Alt + D` (1500x950 floating monitor streaming live ChatGPT tool-call activity).

### Session save/restore

`~/.local/bin/sway-session-save` and `sway-session-restore` are one-shot helpers; there is no resident session daemon. Startup restore is launched once from `60-autostart.conf`, while the enabled `sway-session-save.service` saves on user-manager shutdown and the powermenu saves before explicit logout/reboot/shutdown.

Foot client/server mode requires special cwd handling because all Foot surfaces report the shared server PID to Sway. The saver therefore derives a terminal window's cwd from the Fish/Pure title instead of `/proc/<foot-server-pid>/cwd`, and restore passes the directory explicitly with `footclient -D`. Legacy plain ws1 terminal snapshots containing the erroneous `/` cwd are migrated to `$HOME`; project/other-workspace terminal directories remain unchanged. Foot/Footclient are treated as multi-instance applications.

Night-light session capture and restore read the applied `wl-gammarelay` D-Bus `Temperature` (`q` Kelvin), not whether a `wlsunset` process exists. Below 6500 K is enabled; 6500 K is off. If D-Bus is unavailable, the helpers fall back to `~/.config/nightlight_state` (`on`/`off`); unrecognizable state is left unchanged on restore. The gamma relay remains active even when night light is off because it also serves brightness controls.

`session.json` is replaced atomically only after the new snapshot has been fsynced. A validated current snapshot is atomically copied to `session.json.prev` and to a bounded history of the last 8 known-good snapshots under `~/.config/sway/session/backups/`; invalid snapshots are never promoted into backup slots. Runtime session files remain outside chezmoi. Detailed operation and recovery commands are in `~/.config/sway/SESSION.md` (source: `dot_config/sway/SESSION.md`).

### Cursor Controls (`toggle-cursor-theme` & `adjust-cursor-size`)
* **Current verified size:** `24px` on 2026-11-01. At the current 1.30 output scale the previous 32px raster was visually oversized; 24px is the next native Phinger raster and is now synchronized across Sway, GTK/GSettings, Xresources, and the session environment.
* **Theme Polarity Toggle:** `Alt + Shift + c` switches between `phinger-cursors-gruvbox-material` (dark) and `phinger-cursors-gruvbox-material-light` (light) while preserving the current size.
* **Size Adjustment (one ladder step):**
  * `Alt + Shift + =` (or `Alt + Shift + plus`): next larger size
  * `Alt + Shift + -` (or `Alt + Shift + underscore`): next smaller size
  * The bindings pass `+2` / `-2`. The number is a direction marker, not a magnitude: `phinger-cursors` only contains `24 32 48 64 96 128` images, so a real 2px step cannot exist. One press always moves to the next size in that set.
* **Sizes are a ladder, not free integers:** `phinger-cursors` only ships `24 32 48 64 96 128`. A size absent from the theme is silently substituted at load time, so arbitrary values look like the command did nothing. `adjust-cursor-size 60` snaps to `64` and says so.
* **Both tools are self-reporting.** `adjust-cursor-size` with no arguments prints the size and every consumer; `toggle-cursor-theme status` prints the theme, the size, and the same per-consumer rows. Run either before assuming the setting is broken.
* **Both tools are mutually consistent and write every consumer:** Sway live seat, `~/.config/sway/config.d/10-display.conf` and its chezmoi source, GTK 2/3/4 (`gtk-cursor-theme-size`, `gtk-cursor-theme-name`), GSettings (`cursor-size`, `cursor-theme`), `~/.Xresources` (`Xcursor.size`, `Xcursor.theme`), and `~/.config/environment.d/30-cursor.conf` plus its chezmoi source (`dot_config/environment.d/30-cursor.conf`, tracked since 2026-11-01). Size and theme never overwrite each other.
* **Theme switch also refreshes the X11 fallback layer:** `toggle-cursor-theme` calls `ensure-xcursor-fallbacks` after writing `Xcursor.theme`, which rewrites `~/.icons/default` and `~/.local/share/icons/default` so Xwayland and CEF apps follow the new polarity.
* **Bounds are explicit:** stepping past `24` or `128` prints the bound and exits `2` instead of silently clamping. Running GTK/Qt apps may keep the old cursor until restarted.
* **Optional intermediate-raster builder:** `~/.local/bin/build-cursor-sizes --check` is read-only and reports the sizes actually present in each Phinger theme. The current live themes still expose the native `24 32 48 64 96 128` ladder. Running `build-cursor-sizes` without `--check` is an explicit opt-in operation that resamples missing even sizes under `~/.local/share/icons/phinger-*`; it skips symlink aliases and leaves the pristine copies under `~/.icons` untouched as a restore source.

## 6. Pre-Completion Validation & Verification

Before modifying or reloading Sway configurations:
1. Run the read-only health check: `sway-check`.
2. For direct syntax validation, use `env WLR_BACKENDS=headless WLR_RENDERER=pixman sway -C -c ~/.config/sway/config` so a remote shell does not try to acquire Sway's active DRM/logind seat.
3. Reload through `sway-safe-reload`, which validates first and refuses to replace the working runtime configuration if validation fails.
4. `Win + Shift + R` is bound to `sway-safe-reload`; avoid raw `swaymsg reload` in normal maintenance workflows.

`sway-check` verifies syntax, generated UI scale/chrome state, the live output mode and scale, current binding mode, critical helper executables, and stale `ui-scale` temporary files. It is read-only. Both it and `sway-safe-reload` use headless/pixman validation so remote shells do not compete with the active DRM seat. When `SWAYSOCK` is unset, they discover a Sway IPC socket only if exactly one socket exists for the current UID under `XDG_RUNTIME_DIR` (otherwise normal IPC failure/warning remains); validation must pass before the reload helper sends any IPC reload request.

When staged Sway/UI source changes are committed from the live chezmoi repository, `scripts/git-hooks/pre-commit` runs this validation path and refreshes the auto-managed live Sway snapshot in `docs/system/SYSTEM_CONTEXT.md`. This keeps cross-agent current-state context synchronized without a resident watcher or background daemon.

## 7. System Diagnostics & Architectural Audit (`sway-diagnostics`)

A dedicated, non-invasive system diagnostics auditor is installed at `~/.local/bin/sway-diagnostics` (managed in chezmoi).

### Execution
```bash
sway-diagnostics          # Standard formatted table with ANSI status highlighting
sway-diagnostics -q       # Quiet exit-code mode (0 = healthy, 1 = required component failed)
sway-diagnostics --json   # Machine-readable JSON output for integrations
```

### Architectural Classification
* **REQUIRED CORE:** Sway Compositor (`swaymsg`, syntax validation), Wayland Socket integrity, and `xremap` key remapper.
* **DISPLAY & GPU:** `supergfxctl` mode, NVIDIA driver health/temperature/wattage, focused output mode/165Hz/tearing/scale filter, and hardware vibrance backend (`nvibrant` / `ctm-test`).
* **RESIDENT SERVICES:** Persistent infrastructure only: PipeWire, WirePlumber, XDG Portals (`portal` + `wlr`), `mako`, and `cliphist` (with live `wl-paste` watcher verification).
* **OPTIONAL DESKTOP LAYERS:** Terminal (Alacritty), File Manager (Thunar), Visualizer (Cava), Theme Engine (`theme-set`), and active wallpaper.
* **GAMING STACK:** CS2 launcher, Legendary, Proton runtimes, process niceness scheduler (`ananicy-cpp` vs `gamemoded` isolation), and protected MangoHud configuration.
* **HEALTH & STORAGE:** Failed system/user systemd units count and Btrfs root filesystem capacity/metadata status.

## 9. Window Floating & Dialog Management Rules

Workstation window assignment policy in [`30-window-rules.conf`](file:///home/onyx/.config/sway/config.d/30-window-rules.conf) enforces clean boundaries between persistent tiled productivity applications (e.g., Brave on Workspace 2, Neovim/terminals on Workspace 1) and transient utilities:

- **Yazi shortcut:** `Super+Shift+E` opens `yazi` in a new, normally tiled Foot client (`--app-id=yazi`, working directory `$HOME`, current Foot theme colors). It is on demand and introduces no background service.
- **Thunar Window & Dialog Invariant:** Standard Thunar windows (`app_id="(?i)^thunar$"`) open tiled into the default tabbed layout, taking the full workspace screen without floating over underlying applications. Bound to `$mod+e` (`thunar ~`).
- **Dialog & Archiver Isolation:** Child dialogs and transient prompts (PeaZip archive extraction, Thunar rename, properties, preferences, file operations, and progress dialogs) inherit explicit `floating enable, move position center` rules so progress bars and confirmation prompts remain compact floating overlays above the tiled window.
- **Managed Utility Scratchpad Queue:** `~/.local/bin/scratch-utility-toggle` parks multiple utility/progress windows (PeaZip, transfer dialogs, downloaders) without terminating their work. Only explicitly parked windows receive an ownership mark `__utility_queue_<con_id>`; the helper never adopts unrelated Sway scratchpad windows. It records an ordered, stale-pruned queue at `~/.local/state/scratch/utility-queue.json` with a short `flock` transaction and has no resident daemon. Only one queued overlay is displayed at a time; a focused parked window can be hidden again.
  - `Win + -` hides the focused eligible utility (or top eligible floating utility), otherwise restores the **last viewed** parked window.
  - `Win + Shift + -` / `Win + _` parks the focused eligible window explicitly, including eligible tiled utilities.
  - `Win + Ctrl + -` cycles to the next parked window, parking the currently visible managed one.
  - `Win + Ctrl + Shift + -` opens a Fuzzel picker of currently managed windows for direct selection. `Win + Alt + -` is unchanged and still decreases global UI scale.
- **Scratchpad and Workspace Immunity:** `Ctrl+Space` (`scratch-term`), `Win+n` (Neovim notes), all other dedicated scratchpads, Foot terminals, Neovim/editor windows, and primary browsers are excluded. Browser assignment and tiling on Workspace 2 remain authoritative in `30-window-rules.conf`: neither utility hotkey moves Brave out of Workspace 2. The utility helper does not remove a foreign scratchpad entry even if the foreign window looks like a progress dialog.
- **Meetingly / wl-mirror output policy:** The Meetingly overlay stays floating with a 1px border, while `wl-mirror` stays tiled and borderless. Their rules no longer force `move to output eDP-1`, so they remain on the output/workspace on which they launch even if the built-in panel is later enumerated as `eDP-2`. Actual multi-output placement still depends on the application's launch context and was not tested by this change.
- **Global Floating Decor:** All floating windows inherit `border pixel 2` for crisp visibility against varied wallpapers.

## 10. ChatGPT Desktop Application and Launcher

The packaged ChatGPT Linux app is launched from the system desktop entry `/usr/share/applications/chatgpt.desktop` (`Exec=chatgpt %U`). Its upstream `/usr/bin/chatgpt` launcher reads `~/.config/chatgpt-flags.conf` automatically. The chezmoi source `dot_config/chatgpt-flags.conf` sets `--ozone-platform=wayland` so menu, URL handler, and terminal launches use native Wayland without editing package-managed files. This avoids blurry XWayland resampling at the 1.30 Sway scale; the verified live window was an `xdg_shell` surface with `app_id=chatgpt`.

`Alt+Space` is the Fuzzel application launcher. The old `ChatGPT | https://chatgpt.com` bookmark was removed from `dot_config/rofi/favorites.list`; `sync-fuzzel-favorites` removed its generated `fuzzel-favorite-chatgpt-com.desktop` entry. The native packaged ChatGPT desktop entry is now the only matching menu entry. Other favorites and unrelated browser PWAs remain untouched. `Super+Alt+G` is bound in `dot_config/sway/config.d/40-keybindings.conf` to the one-shot `chatgpt-focus` helper (source: `dot_local/bin/executable_chatgpt-focus`), which focuses an existing `app_id=chatgpt` window or starts `chatgpt` when no such window exists. No resident process or globally changed Sway focus rule is required.

Native Wayland is still experimental for some ChatGPT Linux floating overlays. If necessary, temporarily override the launch arguments or edit the app-specific flags rather than altering the global Sway scaling/focus configuration.
