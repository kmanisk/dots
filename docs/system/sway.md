# Sway Window Manager Architecture & Reference

Architectural standards, window rules, workspace layout, and modular keybindings for Sway (Wayland) on CachyOS.  
Use this document as the single source of truth for window management and display orchestration.

---

## 1. Modular Configuration Architecture (`~/.config/sway/config.d/`)

To ensure token efficiency for AI agents and maintainability for developers, the monolithic 680+ line configuration is structured into logical subcategory files:

| File | Purpose | Lines / Scope |
| :--- | :--- | :--- |
| `00-variables.conf` | Modifiers (`$mod = Mod4`), workspace definitions (`$ws1`–`$ws10`), font, defaults. | Variable declarations |
| `10-display.conf` | `eDP-1` display output mode, 165Hz refresh, cursor theme/size, border styles, theme colors, `apply-vibrance` reload hook. | Display pipeline |
| `20-input.conf` | Keyboard repeat rates, touchpad natural scroll, pointer accel, 3-finger/4-finger gestures. | Input devices |
| `30-window-rules.conf` | Floating utilities (`bluetui`, `wifui`, `rofi-network`, `me3-manager`, `ds3-randomizer`, `cycles-installer`), Thunar rules, Brave tabbed view, Steam shell focus management, Workspace 4 gaming rules. | Window assignments |
| `40-keybindings.conf` | Window navigation, workspace switching, scratchpad toggles, launchers (`rofi-network` on `$mod+Mod1+5`, `bluetui` on `$mod+Mod1+2`), current-theme wallpaper cycling (`Win + Shift + W` / `Win + Ctrl + W`, plus reverse on `Win + Ctrl + Shift + W`), cursor theme/size hotkeys, validated reload on `Win + Shift + R`. Marks system removed 2026-10-18. | Key chords |
| `45-ui-scale.conf` | Output-scale keybindings backed by `ui-scale`; generated runtime state is written to `99-ui-scale.conf`. | Central UI scale controls |
| `50-gaming-mode.conf` | Passthrough gaming mode (`mode "gaming"` via `Alt + Shift + F`), muted shortcuts, game hotkeys. | Gaming isolation |
| `60-autostart.conf` | D-Bus/systemd session imports, daemons (`mako`, `polkit`), night light, wallpaper, game-workspace-daemon. One-shot initialization uses `exec` so ordinary Sway reloads do not restart long-running helpers. | Session bootstrap |
| `70-bar.conf` | Native `swaybar` inclusion and dock/hide state restore. | Status bar |
| `80-theme-colors.conf` | GENERATED by `theme-set` (do not edit). Tabbed windows retain their authored accent as a narrow focus border, but use calm, neutral-blended background surfaces and contrast-checked text for selected/unselected tabs. Generated and live IPC rules match, surviving Sway reloads. | Theme tab/border persistence |
| `99-ui-chrome.conf` | GENERATED by `ui-sync`; scale-adjusted Sway title/tab chrome. | Runtime-generated chrome state |
| `99-ui-scale.conf` | GENERATED by `ui-scale`; persisted runtime output scale. Deliberately not tracked as a fixed chezmoi state. | Runtime-generated scale state |

The root entrypoint (`~/.config/sway/config`) contains:
```ini
include ~/.config/sway/config.d/*.conf
```

## 2. Hardware & Display Pipeline

* **Display Output:** ASUS TUF Gaming F16 built-in display (`eDP-1` in the current 2026-10-31 session; connector names are not assumed permanent).
  * Resolution: `1920x1200` (16:10 aspect ratio).
  * Refresh Rate: approximately `165.004Hz`.
  * Current runtime UI scale: `1.30`.
  * `10-display.conf` owns mode/refresh/adaptive-sync/tearing policy; it deliberately does not hardcode scale.
  * `ui-scale` owns compositor scaling and atomically persists it in generated `99-ui-scale.conf`.
  * `ui-sync` derives scale-aware system chrome and skips writes/reloads when generated content is unchanged. Mako notification/OSD sizing is controlled by the `MAKO_*` values in `~/.config/ui-metrics.conf`; the current compact bases are font 15, padding/margin 8, width 440, and radius 6. With `CHROME_FOLLOW=0` these are divided by output scale, keeping brightness/volume/night-light/general notifications physically compact.
  * Adaptive Sync: `off` (prevents panel backlight flickering/gamma shifts on 165Hz laptop panels).
  * Allow Tearing: `yes` (reduces frame delivery latency in fullscreen gaming).
* **GPU Strategy:**
  * Machine supports `Integrated`, `Hybrid`, and `AsusMuxDgpu`. **Live hardware/firmware and the connected display are authoritative**; `/etc/supergfxd.conf` can say `AsusMuxDgpu` while the ASUS MUX is still Hybrid. The repaired `gpu-switch` now uses only ASUS's delayed `asusctl` firmware queue for changed attributes, verifies each D-Bus pending value, refuses a missing/short-timeout shutdown handler or active VM/VFIO, and reports failed post-reboot mode requests. Installed `supergfxctl 5.2.7` references an obsolete MUX sysfs path, so it is only a read-only status source, not the setter. The keyboard fzf menu uses J/K/Tab and Enter to queue plus request a reboot; direct mode subcommands queue without reboot. The custom `asus-shutdown.service` stop timeout was restored from 5s to the packaged 45s after a failed switch. The original `gpu` symlink and `gpu-mode` remain unchanged. Procedure, verification, and caveats: `docs/display/gpu-switcher.md`.
  * Direct dGPU MUX connects RTX 5050 Mobile directly to eDP-1 with hardware vibrance via `nvibrant`.
  * In `Hybrid` or `Integrated` mode, `sway-run` pins the compositor to the Intel iGPU to allow the RTX 5050 Mobile to power-suspend. `WLR_DRM_DEVICES` must never contain `/dev/dri/by-path/...` symlinks directly because PCI bus addresses contain colons (e.g. `pci-0000:00:02.0-card`), and wlroots splits `WLR_DRM_DEVICES` by `:` delimiter. The launcher resolves `readlink -f` to raw device nodes (e.g. `/dev/dri/card1`).
  * Session autostart on TTY1 (`40-login.fish`) runs without replacing the shell (`exec`) on failure, ensuring that a compositor startup exit drops into an interactive fish shell rather than causing rapid agetty restart loops (`start-limit-hit`). In addition, `getty@tty1.service.d/override.conf` enforces `RestartSec=2s`.

## 4. Window Navigation & Scratchpad Architecture

* **Vim-Style Focus:** `Win + h` (Left), `Win + j` (Down), `Win + k` (Up), `Win + l` (Right).
* **Move Windows:** `Win + Shift + h/j/k/l`.
* **Splits:** `Win + b` controls the current split orientation; the former `Win + Shift + b` split binding is intentionally removed to avoid accidental nested containers beside the browser launcher.
* **Fullscreen:** `Win + f` (Toggle fullscreen).
* **Floating / Tiling Toggle:** `Alt + Shift + Space` (toggles the floating STATE of the focused window).
* **Focus Layer Toggle:** `Shift + Space` (swaps focus between the foreground floating window and the background tiled/tabbed layer underneath, via toggle-floating-focus).
* **Smart Layout Toggle:** `Win + ;` (`~/.local/bin/smart-layout-toggle`) seamlessly toggles windows between side-by-side tiling (`splith`) and tabbed presentation (`tabbed`) in place. It operates directly on the shared parent container without container-nesting marks or `move to mark` wrapping, and flattens orphaned single-child split wrappers so single-window workspaces (such as Brave on Workspace 2) retain edge-to-edge presentation without container representation chrome (e.g. `H[T[...]]`). The legacy `$mod+Shift+b split h` binding adjacent to `$mod+b` (browser launcher) has been removed to prevent accidental container splitting.
* **Window Graceful Close:** `Win + q` (polite WM_DELETE close).
* **Window Force Kill:** `Win + BackSpace` (SIGKILL via `force-kill-window`).
* **Media Controls (Brave / Spotify & MPRIS):**
  * `Win + Alt + P`: Play / Pause toggle (`~/.local/bin/media-ctl play-pause`), reporting track title and artist via Mako OSD.
  * `Win + Alt + .`: Next Track (`~/.local/bin/media-ctl next`).
  * `Win + Alt + ,`: Previous Track (`~/.local/bin/media-ctl prev`).
  * `Win + Alt + /` or `Win + Alt + Shift + P`: Mute / Unmute Brave audio stream (`~/.local/bin/media-ctl mute`) via PipeWire sink-input toggling.
  The helper is one-shot with no resident process. Backward-compatible wrapper `media-play-pause` delegates to `media-ctl`. The Aura preset bindings remain on `Win + Alt + [` (previous preset) and `Win + Alt + ]` (next preset).
* **Windows:** Nano11 is the only installed Windows VM. On workspace 5, Caps+Esc/Super+Alt+W/Super+Ctrl+5 open or focus it; Alt+W and Caps+Tab toggle between Windows workspace 5 and the previous Linux workspace (without starting the guest); Alt+Shift+W opens the five-action management menu. The former X-Lite-specific routing is retired; see the single rebuild guide under `docs/virtualization/windows-vm-rebuild-guide.md`.
* **Current-Theme Wallpapers:** `Win + Shift + W` and `Win + Ctrl + W` advance through the active theme's allowed wallpaper set; `Win + Ctrl + Shift + W` goes backward. GitHub-backed Omarchy themes are theme-scope-authoritative and cycle only their own images under `~/.local/share/theme/wallpapers/upstream/<theme>/`. Discovery version 3 restricts built-ins inside shared monorepos to their canonical wallpaper root (for example Everforest only `themes/everforest/backgrounds/`), and cached cycling applies that filter even before a legacy manifest is repaired. Non-Omarchy palettes cycle only their resolved exact/alias/semantic Omarchy donor set; shared Wallhaven assets are never used at runtime. If no valid image exists, `theme-set` uses the theme's solid background instead of leaking the previous theme's wallpaper. The former `ds3-wallpaper` helper is removed and no keybinding uses the static Dark Souls 3 pack. Wallpaper-cycle keys now exit silently for themes with an explicit solid background, just one cached wallpaper, or zero/one known candidate when the cache is empty. They do not run repository discovery, network fetching, notification, or `wset` when cycling cannot change the image; multi-image cycling and explicit `fetch`/`refresh` remain available.
* **Animated Wallpapers (`oguri`):** For animated GIF backgrounds, `oguri` (`oguri-git`) runs on Wayland layer-shell (`ZWLR_LAYER_SHELL_V1_LAYER_BACKGROUND`). Controlled via `oguri-wallpaper` (`oguri-wallpaper <image>`, `--toggle`, `--stop`, `--status`) and on-demand `oguri.service`. When stopped, Sway's static wallpaper is immediately restored without flickering or compositor restart. See `docs/display/oguri.md`.

### Launcher entry hygiene (verified 2026-11-10)

The application launcher is **Alt+Space** (Fuzzel), while **Ctrl+Space** opens the Foot scratchpad; those bindings are unchanged. Fuzzel reads visible XDG desktop entries from `~/.local/share/applications` and system application directories, plus a recency ranking file at `~/.cache/fuzzel`. An application uninstall does not necessarily remove a manually created desktop entry.

A targeted audit found two broken **visible** user entries and no broken top-level commands among visible system entries. The removed Vesktop package left behind an unowned `vesktop.desktop` pointing to missing `/usr/bin/vesktop`. Only that desktop file and its one Fuzzel recent-app cache line were deleted, without clearing other launch history. `dot_config/mimeapps.list` was updated so the `discord://` URL scheme opens the installed official Discord application; live MIME preferences for Codex and RAR were retained in chezmoi. btop is still installed, but its desktop entry used uninstalled `alacritty`; `dot_local/share/applications/btop.desktop` now runs `footclient --app-id=btop --title=btop -e btop`, retaining the existing floating Sway `app_id=btop` rule. No Waydroid exports, hidden file-type handlers, other installed applications, packages, or services were removed.

`proton-anger-foot.desktop` is now managed under `dot_local/share/applications/` as well. Its Alt+Space entry and the Alt+G `dot_config/rofi/custom-games.list` entry explicitly pass `--lsfg 2x`, while MangoHud remains disabled and the existing game prefix is unchanged. This is a configuration check, **not a successful in-game LSFG rendering test**. The updated desktop files passed `desktop-file-validate`; `update-desktop-database` refreshed the user applications directory; `xdg-mime query default x-scheme-handler/discord` returns `discord.desktop`. A rollback copy of the affected launcher, MIME, game registry and Fuzzel ranking files is at `~/.local/state/launcher-cleanup-20261110/`. No periodic scan or daemon is added.

### Alt+Space application launcher

`Alt + Space` launches native Wayland Fuzzel. Its compact proportions remain `width=36` and `lines=10`; `image-size-ratio=0` disables the separate large selected-app preview. `ui-sync` derives `line-height` from `FUZZEL_LINE_HEIGHT=26` in `~/.config/ui-metrics.conf`; at the current 1.30 compositor scale this generates a 20px logical row, about a 26px physical row/icon target, while the font remains 14px logical. This keeps the original minimal shape while making list icons modestly larger than the old font-metric default.

### Bookmarks & Web Favorites Menu (`Alt + u` / `Alt + b` / `Alt + Shift + b`)

`Alt + u`, `Alt + b`, and `Alt + Shift + b` open `~/.local/bin/rofi-favorites`, a dedicated bookmarks picker reading directly from `~/.config/rofi/favorites.list`. Unlike `rofi-websearch` (`Alt + s` / `Win + /`), which queries search engines, `rofi-favorites` lists direct website bookmarks (Amazon, YouTube, GitHub profile, ASUS TUF & Dolby hardware drivers inventory, ArchWiki, ProtonDB, Claude AI, etc.) with native SVG icon hints in Fuzzel on Wayland (falling back to Rofi). ### Video Players & Media (`mpv`, `vlc`, `celluloid`, `totem`, `amberol`)

Media players open **tiled in tabbed view** (`floating disable, layout tabbed, focus`) on the active workspace. To prevent dropdown scratchpads (`scratch-term` via `Ctrl+Space`) from hovering over and obscuring the tabbed player when `mpv` is launched from the terminal, `~/.config/fish/functions/mpv.fish` automatically dismisses `scratch-term` into the scratchpad upon launch, immediately revealing the tabbed video surface. `mpv`, `vlc`, and `celluloid` are also protected in `~/.local/bin/scratch-utility-toggle` so `Win+Shift+-` cannot park active video playback into the utility queue.

### ChatGPT Window Rules & Scratchpad Protection

Native ChatGPT Wayland/Electron windows (`app_id="chatgpt"`) are not pinned to a static workspace, but open dynamically on whichever workspace they are launched from with `border pixel 2` and `floating disable` (preventing CSD borderless floating artifacts). ChatGPT is protected in `PROTECTED` within `~/.local/bin/scratch-utility-toggle` to prevent accidental scratchpad banishment. Summoning via `~/.local/bin/chatgpt-focus` (`Win+Alt+g`) discovers running instances and summons them to the current active workspace (`move to workspace current, focus`), or launches a new instance on demand.

### Media playback, browser audio streams, and MPRIS controls (verified 2026-11-13)

Global media controls and browser stream management are handled through the unified one-shot helper `~/.local/bin/media-ctl` (with backward-compatible alias `~/.local/bin/media-play-pause`):

* **Keybindings (60% ANSI ergonomics):**
  * `Win + Alt + P`: Play / Pause toggle (`media-ctl play-pause`). Queries MPRIS players targeting `brave,spotify` first, with global fallback. Displays a lightweight Mako OSD with track title and artist.
  * `Win + Alt + .`: Next Track (`media-ctl next`). Sends skip-forward and updates track OSD.
  * `Win + Alt + ,`: Previous Track (`media-ctl prev`). Sends skip-backward and updates track OSD.
  * `Win + Alt + /` or `Win + Alt + Shift + P`: Targeted stream mute/unmute (`media-ctl mute`). Queries PipeWire for all active sink-inputs matching `application.name = "Brave"` and toggles their mute state atomically without stopping track playback.

* **Browser Audio & PipeWire Architecture:**
  * Chromium/Brave registers all audio streams under generic process metadata (`application.name = "Brave"`, `media.name = "Playback"`) without exposing individual tab URLs or site domains to PipeWire. Consequently, stream muting silences the entire browser audio pipeline.
  * MPRIS controls (`playerctl`) interact with the browser's active HTML5 Media Session. Standard transport methods (`PlayPause`, `Next`, `Previous`, `Stop`) are supported. `LoopStatus` and `Shuffle` are omitted by Chromium for web tabs.
  * When a Bluetooth audio sink (such as `Boult BassBox`, `bluez_output.*`) connects, WirePlumber automatically switches the default audio sink to Bluetooth. Active browser streams follow the default sink. To redirect audio back to internal laptop speakers without disconnecting Bluetooth, set `pactl set-default-sink alsa_output.pci-0000_00_1f.3.analog-stereo`.

* **Web Apps (PWAs) & Window Merging:**
  * Websites installed as PWAs (e.g. Spotify Web App) run as standalone top-level Wayland windows without a browser tab bar.
  * Sway can group them into compositor-managed tabs via `smart-layout-toggle` (`Win + ;`).
  * To merge a standalone PWA window back into an internal tab within the main Brave browser window, use the window menu (three dots in the top-right header) and select **Open in Brave**. Alternatively, the browser extension *Window Merger* maps tab consolidation to an in-browser keybinding (e.g. `Alt + Shift + M`).

### Utility TUI Windows

The compact hardware/network TUIs use dedicated Foot client overrides instead of inheriting the global terminal font: `wifui` and `bluetui` use 15pt Iosevka Mono in centered 900x600 floats; `rogtui` uses the same 15pt override in a centered 900x680 float. This keeps utility panels readable at the current output scale without changing `foot.ini` globally.

### Scratchpads (`~/.local/bin/scratch-toggle`)
Canonical dimensions: `1700x1050` base geometry, centered on display. On scaled Wayland outputs (such as 1.30x on 1920x1200), `scratch-toggle` caps window dimensions to `SCRATCH_SCALE_PCT` (default 90%, producing 1328x830 logical pixels) to ensure full horizontal width for multi-column terminal applications (such as btop memory and disks meters) while remaining centered. Windows are **lazy-loaded on demand** on initial hotkey press to eliminate idle RAM waste:
1. **Terminal Scratchpad:** `Alt + \`` or `Ctrl + Space`. Its dedicated Foot override is 16 pt, slightly smaller than the global terminal so the scratch window fits more output without changing other terminals.
2. **Notes Scratchpad:** `Win + n` (Spawns/toggles Neovim on `~/notes.md`).
3. **Spotify Scratchpad:** `Win + m` (Spawns/toggles Spotify window).
4. **Video Player (mpv):** `Win + -` or `Win + _` (1280x720 floating scratchpad).
5. **ChatGPT Local Coder Monitor Scratchpad:** `Win + Alt + D` (1500x950 floating monitor streaming live ChatGPT tool-call activity, 15 pt font).

**Workspace Guard Rules:**
Scratchpad triggers are blocked strictly on **Workspace 4 (Gaming)**, or while a game window is focused (`steam_app_*`, `cs2`, `gamescope`, `eldenring`, `steam_proton`, `farcry3`, `gtaiv`). Scratchpads are permitted on all other workspaces (including Workspace 5 - Windows/Looking Glass, Workspace 3 - Steam, Workspace 1, Workspace 2, and empty workspaces when no window behind it is open).

### Session save/restore

`~/.local/bin/sway-session-save` and `sway-session-restore` are one-shot helpers; there is no resident session daemon. Startup restore is launched once from `60-autostart.conf`, while the enabled `sway-session-save.service` saves on user-manager shutdown and the powermenu saves before explicit logout/reboot/shutdown.

**Clean shell restoration and daemonless architecture (verified 2026-11-21):**
- All terminal windows restore strictly as clean, interactive Fish shells (`footclient -D <cwd>`) on their assigned workspaces. Saved sessions normalize terminals to `footclient` and never record or automatically relaunch CLI agents, conversations, or subshell tools (AGY, Codex, OpenCode, Claude, Gemini, Neovim, etc.). When the user manually opens or types `agy`, `codex`, or `opencode`, the tool starts interactively with existing authentication and history preserved.
- Foot client/server cwd handling: because all Foot surfaces share the server PID, working directories are recovered through a multi-tier pipeline:
  1. Fish/Pure window title parsing (`<cwd> - fish` or `<cwd>: <cmd> - <subcmd>`), with full support for paths containing spaces and `~` expansions.
  2. Process-tree descendant inspection (`find_foot_child_cwd`) under the Foot server PID for applications that override the window title (such as `btop`, `top`, or `nvim`).
  3. Safe fallback to `$HOME` if the directory does not exist or if the server reported root `/`.
- Self-healing snapshot loading: `sway-session-restore` automatically falls back to `session.json.prev`, then historical backups under `~/.config/sway/session/backups/`, if `session.json` is missing or corrupted.
- Cold-boot fallback: only runs when no valid session snapshot exists anywhere. When a valid snapshot is restored, intentionally closed applications are never resurrected.
- Focus restoration: snapshots record `focused_workspace` so restore returns focus directly to the user's active workspace.
- Duplicate prevention: real Foot windows are counted so multi-instance terminals are preserved without surplus tabs, and single-instance applications (such as Brave) are never duplicated.

**Authentication and GNOME Keyring resolution (verified 2026-11-21):**
- TTY1 autologin (`agetty --autologin onyx`) does not provide a password to PAM, leaving GNOME Keyring's `login.keyring` locked at boot.
- The recurring startup popup ("The login keyring did not get unlocked") was traced to `sway-session-restore` previously restoring `footclient agy` at boot, which queried Secret Service before the user logged in. By eliminating CLI auto-start at boot and because Brave uses `--password-store=basic`, no application queries Secret Service on startup, completely eliminating the startup prompt.
- For manual launches, `/home/onyx/.local/bin/agy` sets `antigravity-keyring-unavailable` when the keyring is locked, enabling AGY's composite token storage to load its valid file-based OAuth token (`~/.gemini/antigravity-cli/antigravity-oauth-token`) directly without blocking or prompting, preserving `login.keyring` encryption without weakness.
- **Concord-specific correction (2026-11-21):** The prior agent-added `~/.local/bin/concord` preflight still forced a GNOME unlock dialog on every locked-keyring session, so it was removed (live and chezmoi). Concord 2.7.1 now explicitly uses `credentials.store = "plain"` in `dot_config/concord/config.toml`, avoiding Secret Service on Concord startup while preserving passwordless TTY1 login and existing shortcuts. **Concord's Discord token will be saved unencrypted** under user-only `~/.local/state/concord` (`0700` parent, `0600` file). The original encrypted keyring remains intact; no password or token was exposed/migrated. One-time new Discord login may be needed, and this doesn't prevent other apps from requesting the locked GNOME keyring. See `docs/system/concord-keyring.md`.

Night-light session capture and restore read the applied `wl-gammarelay` D-Bus `Temperature` (`q` Kelvin), not whether a `wlsunset` process exists. Below 6500 K is enabled; 6500 K is off. If D-Bus is unavailable, the helpers fall back to `~/.config/nightlight_state` (`on`/`off`); unrecognizable state is left unchanged on restore. The gamma relay remains active even when night light is off because it also serves brightness controls. **Current 2026-11-10:** Night-light toggles and 100 K adjustments use the **original instant** `wl-gammarelay` D-Bus updates; the temporary ~280 ms ramp was removed. Brightness and PipeWire volume were also restored to their original one-step controls. No extra gamma daemon, compositor fade or new service was introduced. See `docs/system/interactive-control-smoothing.md` for the rollback record.

`session.json` is replaced atomically only after the new snapshot has been fsynced. A validated current snapshot is atomically copied to `session.json.prev` and to a bounded history of the last 8 known-good snapshots under `~/.config/sway/session/backups/`; invalid snapshots are never promoted into backup slots. Runtime session files remain outside chezmoi. Detailed operation and recovery commands are in `~/.config/sway/SESSION.md` (source: `dot_config/sway/SESSION.md`).

### Cursor Controls (`toggle-cursor-theme` & `adjust-cursor-size`)
* **Current verified size:** `24px` on 2026-11-01. At the current 1.30 output scale the previous 32px raster was visually oversized; 24px is the next native Phinger raster and is now synchronized across Sway, GTK/GSettings, Xresources, and the session environment.
* **Theme Polarity Toggle:** `Alt + Shift + c` switches between `phinger-cursors-gruvbox-material` (dark) and `phinger-cursors-gruvbox-material-light` (light) while preserving the current size.
* **Size Adjustment (one ladder step):**
  * `Alt + Shift + =` (or `Alt + Shift + plus`): next larger size
  * `Alt + Shift + -` (or `Alt + Shift + underscore`): next smaller size
  * The bindings pass `+2` / `-2`. The number is a direction marker, not a magnitude: `phinger-cursors` only contains `24 32 48 64 96 128` images, so a real 2px step cannot exist. One press always moves to the next size in that set.
* **Sizes are a ladder, not free integers:** `phinger-cursors` only ships `24 32 48 64 96 128`. A size absent from the theme is silently substituted at load time, so arbitrary values look like the command did nothing. `adjust-cursor-size 60` snaps to `64` and says so.
* **Both tools are self-reporting.** `adjust-cursor-size` with no arguments prints the size and every consumer; `toggle-cursor-theme status` prints the theme, the size, and the same per-consumer rows. Run either before assuming the setting is broken.
* **Both tools are mutually consistent and write every consumer:** Sway live seat, `~/.config/sway/config.d/10-display.conf` and its chezmoi source, GTK 2/3/4 (`gtk-cursor-theme-size`, `gtk-cursor-theme-name`), GSettings (`cursor-size`, `cursor-theme`), `~/.Xresources` (`Xcursor.size`, `Xcursor.theme`), and `~/.config/environment.d/30-cursor.conf` plus its chezmoi source (`dot_config/environment.d/30-cursor.conf`, tracked since 2026-11-01). Size and theme never overwrite each other.
* **Theme switch also refreshes the X11 fallback layer:** `toggle-cursor-theme` calls `ensure-xcursor-fallbacks` after writing `Xcursor.theme`, which rewrites `~/.icons/default` and `~/.local/share/icons/default` so Xwayland and CEF apps follow the new polarity.
* **Bounds are explicit:** stepping past `24` or `128` prints the bound and exits `2` instead of silently clamping. Running GTK/Qt apps may keep the old cursor until restarted.
* **Optional intermediate-raster builder:** `~/.local/bin/build-cursor-sizes --check` is read-only and reports the sizes actually present in each Phinger theme. The current live themes still expose the native `24 32 48 64 96 128` ladder. ## 6. Pre-Completion Validation & Verification

Before modifying or reloading Sway configurations:
1. Run the read-only health check: `sway-check`.
2. For direct syntax validation, use `env WLR_BACKENDS=headless WLR_RENDERER=pixman sway -C -c ~/.config/sway/config` so a remote shell does not try to acquire Sway's active DRM/logind seat.
3. Reload through `sway-safe-reload`, which validates first and refuses to replace the working runtime configuration if validation fails.
4. `Win + Shift + R` is bound to `sway-safe-reload`; avoid raw `swaymsg reload` in normal maintenance workflows.

`sway-check` verifies syntax, generated UI scale/chrome state, the live output mode and scale, current binding mode, critical helper executables, and stale `ui-scale` temporary files. It is read-only. Both it and `sway-safe-reload` use headless/pixman validation so remote shells do not compete with the active DRM seat. When `SWAYSOCK` is unset, they discover a Sway IPC socket only if exactly one socket exists for the current UID under `XDG_RUNTIME_DIR` (otherwise normal IPC failure/warning remains); validation must pass before the reload helper sends any IPC reload request.

When staged Sway/UI source changes are committed from the live chezmoi repository, `scripts/git-hooks/pre-commit` runs this validation path and refreshes the auto-managed live Sway snapshot in `docs/system/SYSTEM_CONTEXT.md`. This keeps cross-agent current-state context synchronized without a resident watcher or background daemon.

## 9. Window Floating & Dialog Management Rules

**Workspace 2 Brave floating-state recovery, 2026-11-11:** The user reported that the main `brave-origin` window occupied almost the entire display while floating over other tabs. Fresh Sway IPC showed window ID **264**, `app_id=brave-origin`, on workspace 2 at `{x:17,y:-4,width:1480,height:927}`, with `floating=user_on` and **no tiled children**. This was an already-mapped window; Sway evaluates its `for_window ... floating disable` rules **only on map**, so those rules did not retroactively convert the existing float. The original action responsible for the manual floating state could not be recovered from the current tree.

Applied **only** `[con_id=264] floating disable` through live Sway IPC, without restarting Brave. Verification: the same ID **264** is now `floating=auto_off`, occupies the full workspace rectangle `{x:0,y:0,width:1476,height:923}` as a child of existing `layout=tabbed` container ID 427; workspace 2 has no floating nodes. The source and live window rules already match and retain `floating disable` on new browser maps; `00-variables.conf` retains `tiling_drag disable`, blocking Sway's ordinary tiling-to-float mouse drag, and `Alt+Shift+Space` invokes `toggle-floating-strict` (verified browser dry run chooses `retile`, not `toggle`). Real browser dialogs are still allowed to float. `sway-check` reported 0 failures/0 warnings; no config reload, daemon, browser relaunch, screen-scale change or extra process was needed. **Limitation:** Sway does not reapply `for_window` rules to existing windows following arbitrary external `swaymsg floating enable` commands; an absolute invariant against such out-of-band actions would require an event watcher, intentionally not added under the no-resident-service policy. `Win+Shift+Space` is the existing explicit retile escape hatch.

Workstation window assignment policy in [`30-window-rules.conf`](file:///home/onyx/.config/sway/config.d/30-window-rules.conf) enforces clean boundaries between persistent tiled productivity applications (e.g., Brave on Workspace 2, Neovim/terminals on Workspace 1) and transient utilities:

- **Yazi shortcut:** `Super+Shift+E` opens `yazi` in a new, normally tiled Foot client (`--app-id=yazi`, working directory `$HOME`, current Foot theme colors). It is on demand and introduces no background service.
- **Thunar Window & Dialog Invariant:** Standard Thunar windows (`app_id="(?i)^thunar$"`) open tiled into the default tabbed layout, taking the full workspace screen without floating over underlying applications. Bound to `$mod+e` (`thunar ~`).
- **Dialog & Archiver Isolation:** Child dialogs and transient prompts (PeaZip archive extraction, Thunar rename, properties, preferences, file operations, and progress dialogs) inherit explicit `floating enable, move position center` rules so progress bars and confirmation prompts remain compact floating overlays above the tiled window.
- **Managed Utility Scratchpad Queue:** `~/.local/bin/scratch-utility-toggle` parks multiple utility/progress windows (PeaZip, transfer dialogs, downloaders) without terminating their work. Only explicitly parked windows receive an ownership mark `__utility_queue_<con_id>`; the helper never adopts unrelated Sway scratchpad windows. It records an ordered, stale-pruned queue at `~/.local/state/scratch/utility-queue.json` with a short `flock` transaction and has no resident daemon. Only one queued overlay is displayed at a time; a focused parked window can be hidden again.
  - `Win + -` hides the focused eligible utility (or top eligible floating utility), otherwise restores the **last viewed** parked window.
  - `Win + Shift + -` / `Win + _` parks the focused eligible window explicitly, including eligible tiled utilities.
  - `Win + Ctrl + -` cycles to the next parked window, parking the currently visible managed one.
  - `Win + Ctrl + Shift + -` opens a Fuzzel picker of currently managed windows for direct selection. `Win + Alt + -` is unchanged and still decreases global UI scale.
- **Scratchpad and Workspace Immunity:** `Ctrl+Space` (`scratch-term`), `Win+n` (Neovim notes), all other dedicated scratchpads, Foot terminals, Neovim/editor windows, and primary browsers are excluded. Browser assignment and tiling on Workspace 2 remain authoritative in `30-window-rules.conf`: neither utility hotkey moves Brave out of Workspace 2. The utility helper does not remove a foreign scratchpad entry even if the foreign window looks like a progress dialog.
- **Meetingly / wl-mirror output policy:** The Meetingly overlay stays floating with a 1px border, while `wl-mirror` stays tiled and borderless. Their rules no longer force `move to output eDP-1`, so they remain on the output/workspace on which they launch even if the built-in panel is later enumerated as `eDP-2`. Actual multi-output placement still depends on the application's launch context and was not tested by this change.
- **Waydroid Tabbed Window Policy:** Waydroid container surfaces and individual Android application windows (`app_id="(?i)^waydroid.*"` and `class="(?i)^waydroid.*"`) are assigned `fullscreen disable, floating disable, layout tabbed, focus`. This keeps Android occupying the container space as a tab in the workspace's tabbed layout (allowing seamless tab navigation with the Sway tab bar visible) while strictly preventing side-by-side split tiling.
- **Global Floating Decor:** All floating windows inherit `border pixel 2` for crisp visibility against varied wallpapers.
