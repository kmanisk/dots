### Clock-watchdog crash isolated during clean acceptance

The first 30-minute host observation completed without source loss, but later native Windows evidence exposed an unexpected guest restart while QEMU stayed alive. A second USB-free clean boot then lost LGMP again after **99 seconds**: host CPU rose to **5.015 cores**, and Windows automatically restarted. This repair did not issue either reset. The original X-Lite registry had `CrashDumpEnabled=0`, `LogEvent=0`, `AutoReboot=1`, so the earlier restart had no bugcheck record/dump.

`Configure-Guest-CrashEvidence.ps1` was parsed and executed inside Windows. It requires elevated Windows 10 build 19045 and a boot-volume paging file of at least 2 MiB; it exports the registry and creates a two-value rollback before setting **CrashDumpEnabled=3 / LogEvent=1**. Existing **16 MiB paging file**, automatic restart and all services remain unchanged. The subsequent clean boot produced System event **1001**: **`0x00000101 CLOCK_WATCHDOG_TIMEOUT`**, timeout `0x10`, unresponsive vCPU index **6**, plus `C:\Windows\Minidump\110726-3843-01.dmp` (1,363,083 bytes). The saved host copy's SHA256 is `b1ea17d938a7c0cd5c0c30d61f3a19a22597f10907414cd4e15e3550b6efa971`. This identifies a CPU clock-interrupt watchdog failure for that event, not an Intel/IDD faulting driver. A symbolized kernel stack analysis has not been performed.

[Microsoft's 0x101 reference](https://learn.microsoft.com/en-us/windows-hardware/drivers/debugger/bug-check-0x101---clock-watchdog-timeout) describes the missing secondary-processor clock interrupt. [QEMU's Hyper-V reference](https://www.qemu.org/docs/master/system/i386/hyperv.html) documents `hv-relaxed` for hypervisor watchdog timeout handling; Nano11's full Hyper-V exposure already includes it. After preserving the dump and another managed clean stop/offline check, Win10 added **only `hv-relaxed=on`** to the prior clock/timer set. This is a controlled compatibility test: absence of reboot alone is not enough; continuing guest progress, CPU usage and post-idle input/frame tests must also pass. The IDD stall watchdog has not been disabled. No CPU limit or automatic reset watcher was introduced.

### Mandatory gates for a reusable GPU passthrough / Looking Glass setup program

1. **Identify active host display GPU and protected PCI functions** (Sway output connector and its GPU), IOMMU grouping, NVIDIA/Intel PF bindings, and any other VM owner. Refuse to detach a host display GPU. Only allow explicitly selected guest devices; multi-GPU selection must never implicitly steal the compositor GPU.
2. **Check SR-IOV capability, kernel-module compatibility and boot flags** before creating a VF; recheck after every reboot. Handle VF disappearance and changed group numbers; ensure group isolation and vfio permissions. Keep a no-VF fallback.
3. **Probe guest boot media and actual architecture**. The X-Lite ISO failed OVMF optical boot, succeeded with SeaBIOS; unsigned/modified ISO contents may be missing Windows APIs, guest drivers, updates or security protections. Do not assume all Windows versions offer the same WDDM/IDD path.
4. **Pin and verify exact signed Intel Windows driver and matched LG IDD/client builds**; do not use test-signing, force-driver installs, or Code 28 workarounds as silent defaults. Distinguish successful PnP Code 0 from separately verified D3D11 hardware adapter creation.
5. **Match IDD dimensions, refresh and KVMFR sizing** (64 MiB presently verified for SDR 1920x1200); increase only if evidence shows insufficient buffer, and do not silently change Nano11's shared module. Verify actual LGMP frames and UPS, not only an advertised 165 Hz mode or an opened client window.
6. **Avoid multiple Windows virtual primary monitors**. QEMU VGA primary + LG IDD secondary made applications invisible; use IDD-only GPU mode with a separately tested VGA recovery boot. Treat RDP/guest login, Windows clock/DPI, per-monitor EDID and guest-vs-host resizing as distinct configuration stages.
7. **Keep network opt-in and avoid accidental exposure**. Standard QEMU user NAT needs a Windows-compatible virtual NIC and DHCP, and outbound access is not the same as a secure or supported Windows installation. Default deny public host forwards, bridge creation, and Windows blank-password RDP.
8. **Do not confuse driver idle cost with removable bloat**. Measure WUDFHost/lgidd and interrupt/DPC CPU over repeated samples. Disabling the UMDF service is not an optimization. Verify input, sound, clipboard and fallback before declaring success.
9. **Do not type into an actively used guest desktop from an agent**. Synthetic HMP/VNC keystrokes race host compositor focus and user work; capture a baseline, offer a visible and user-controlled one-shot guest configuration script, and verify its output log before marking applied.
10. **Validate rollback and idempotency**. Guarded clean Windows shutdown (ACPI or in-guest command), image ownership, separate QEMU transient unit, on-demand shared buffer and a backed-up guest registry are required. Do not manipulate a live QCOW2, FAT image or host GPU binding during another VM session. Run cold-boot and recovery-mode checks after each permanent change.
